Premium — Frames Scrub (WebMotion)

Liga o scroll da página a uma sequência de imagens WebP — o mesmo efeito de "vídeo que toca conforme você rola" do sw-premium-video-scrub, só que em vez de um arquivo de vídeo, são quadros individuais gerados pelo WebMotion Studio (leve, sem depender de codec de vídeo, com pausas nítidas em qualquer quadro). Inclui um sistema de legendas sincronizadas pra colocar texto por cima da animação sem escrever nenhum cálculo de scroll na mão.

Comece por aqui — sem pular

O código explicado, linha por linha

Antes de qualquer termo técnico: isto aqui é o código inteiro e completo que faz a animação do Exemplo 1 (mais abaixo) funcionar. Não falta nada, não tem pedaço escondido. Vamos ler ele junto, linha por linha, como se fosse a primeira vez que você vê HTML.

<div id="ex1" style="..."> — a moldura

Um <div> é só uma "caixa" invisível que agrupa coisas — o tijolo mais básico de qualquer página. Pense nela como uma moldura de foto na parede: ela decide o tamanho e o formato do espaço. id="ex1" é um apelido que você inventa pra essa caixa — serve só pra poder "chamar" ela por nome mais adiante (repare que usamos #ex1 três linhas abaixo — é o mesmo apelido). Dentro do style: height:100vh = "essa moldura tem a altura exata da tela"; overflow:hidden = "qualquer coisa que passar do tamanho da moldura fica escondida, não vaza pra fora"; background:#000 = fundo preto enquanto a imagem carrega, só estética.

<div sw-premium-frames-scrub="true" ...> — a foto

Essa é a caixa de dentro da moldura — é ela que faz a mágica. sw-premium-frames-scrub="true" é literalmente um interruptor: "framework, liga a animação aqui". Sem essa linha, é só uma caixa vazia sem fazer nada.

sw-premium-frames-src="assets/frames-produto/frame_"

Onde estão as imagens e como o nome delas começa. Se seus arquivos se chamam frame_001.webp, frame_002.webp..., você escreve só até o frame_ — o framework completa sozinho com o número e o final do nome (as próximas duas linhas explicam essas duas partes).

sw-premium-frames-count="96"

Quantas imagens existem, no total. Se o seu WebMotion gerou 50 quadros, aqui vira 50. É o único valor obrigatório — sem ele, nada funciona.

sw-premium-frames-pad="3"

Quantos números tem no nome do arquivo. 001 tem 3 números → é 3. Isso é só o "final" do nome que a linha de cima (frames-src) não incluiu.

sw-premium-frames-ext="webp"

O formato do arquivo de imagem. O WebMotion Studio sempre gera .webp, então na prática você quase nunca vai precisar mudar essa linha.

sw-premium-scroll-pin="#ex1"

Aqui usamos o apelido ex1 de novo (o # na frente quer dizer "ache pelo apelido"). Essa linha diz: trave a moldura na tela enquanto o usuário rola — ela não sobe nem desce, só a "foto" de dentro troca de quadro. Sem essa linha, a animação ainda funciona, mas a seção sobe e desce livre, sem travar.

sw-premium-scroll-end="+=250% bottom"

Quanto o usuário precisa rolar pra ver a animação do primeiro ao último quadro. 250% = "duas telas e meia de rolagem". Quer que acabe mais rápido? Baixa o número (ex: 150%). Quer mais devagar? Aumenta (ex: 400%).

sw-premium-scroll-scrub="0.4"

O quanto o movimento fica "grudado" no seu dedo/mouse. 0 = seco, exatamente junto com o scroll. Números maiores (1, 2...) = fica um pouco "atrasado", com sensação mais suave/pesada — como se tivesse inércia.

É isso — não tem mais nada escondido. Nenhum JavaScript seu é necessário; o framework lê essas linhas sozinho quando a página carrega. As seções abaixo aprofundam cada parte, mas se você só quiser copiar, colar e trocar os números, já sabe o suficiente pra seguir.

Se quiser entender por dentro (opcional, mais técnico)

Você não precisa saber nada disso pra usar o componente — é só curiosidade de como ele funciona por trás das cortinas:

  1. Pré-carrega todos os quadros no navegador assim que a página abre (evita "piscar" na primeira vez que cada quadro aparece).
  2. Cria uma única <img> internamente e vai trocando o src dela conforme você rola — não empilha as N imagens no DOM.
  3. Usa o GSAP ScrollTrigger (o mesmo motor por trás de todo o SW Premium) pra calcular o progresso do scroll — 0% no primeiro quadro, 100% no último — com suavidade e pin (travar a seção na tela) configuráveis.
  4. Se você marcar textos com sw-premium-frames-step, eles aparecem/somem sozinhos de acordo com a mesma régua de progresso — sem você calcular nada.

Tabela de referência rápida

Pra quando você já entendeu a explicação acima e só quer conferir um valor específico depois. Não precisa ler tudo agora.

Atributo Tipo Descrição
sw-premium-frames-scrub true Ativa o componente no elemento (uma <div>, normalmente).
sw-premium-frames-src caminho + prefixo Início do nome do arquivo, ex: "frames/frame_" (o componente completa com o número e a extensão).
sw-premium-frames-count número Obrigatório. Quantos quadros existem, ex: 96.
sw-premium-frames-pad número Zeros à esquerda no número do arquivo. Padrão 3 (001, 002...). Use 2 se seus arquivos forem 01, 02.
sw-premium-frames-ext texto Extensão do arquivo. Padrão "webp" (o formato que o WebMotion Studio gera).
sw-premium-frames-step "inicio-fim" Vai num filho direto do elemento (não no elemento principal) — mostra esse filho só entre os quadros indicados, ex: sw-premium-frames-step="1-32".
sw-premium-scroll-pin seletor CSS Elemento a ser travado (pin) na tela durante a animação. Sem isso, a animação toca enquanto a seção passa pela tela normalmente, sem travar nada.
sw-premium-scroll-start / -end string GSAP Onde a animação começa/termina em relação ao scroll. Ex: "+=250% bottom" = precisa rolar 2,5× a altura da tela.
sw-premium-scroll-scrub número Suavidade/inércia. 0 = 1:1 com o scroll, sem atraso. 0.4–0.6 = suave (recomendado). 2+ = bem "atrasado", cinematográfico.

Como montar do zero

1

Gere os quadros no WebMotion Studio

Suba o vídeo, escolha o formato "Frames", defina o trecho (início/duração), o tamanho e o FPS (que agora controla de verdade quantos quadros saem: quadros = duração × fps). Baixe o .zip e extraia — os arquivos já vêm numerados _wm_<id>_001.webp, _002.webp...

2

Organize a pasta no seu projeto

Renomeie pra um padrão simples e sequencial (ex: frame_001.webp ... frame_096.webp) numa pasta tipo assets/frames-produto/. A ordem e a numeração são tudo — não pule números.

3

Escreva o bloco HTML

Um contêiner com altura definida (a "tela" onde o vídeo aparece) e, dentro dele, a <div> com os atributos sw-premium-frames-*. Nenhum JavaScript seu é necessário — o framework faz o resto sozinho quando a página carrega.

4

(Opcional) Adicione legendas

Dentro do mesmo contêiner, adicione blocos de texto com sw-premium-frames-step="inicio-fim" apontando pros números de quadro onde cada texto deve aparecer. Veja o quadro na hora de decidir os números — não tem mistério, é só "esse texto some no quadro 32" (ver Exemplo 2 abaixo).

O padrão mais usado na internet

Exemplo 2b — Imagem fixa, texto rolando 100% normal

Este é o efeito que a maioria dos sites usa (Apple, Stripe, portfólios, "scrollytelling" em geral): a imagem fica grudada na tela enquanto o texto rola exatamente como um site comum — nenhum atributo especial no texto, nenhuma pausa calculada, nenhum "peso". São só parágrafos normais, um embaixo do outro, que o navegador já sabe rolar sozinho.

Por que funciona: o truque de 2 linhas

position: sticky; top: 0 na imagem (.pc-imagem) faz ela grudar no topo assim que chega lá, e ficar grudada até a caixa em volta dela acabar — é "sticky", gruda de verdade, sem precisar de nenhum JavaScript. O texto (.pc-conteudo) vem depois dela no HTML — normalmente ele começaria uma tela inteira mais abaixo. O margin-top: -100vh (100vh = uma tela de altura, negativo = "sobe") puxa ele de volta pra cima, fazendo começar bem no topo da imagem — por isso ele parece estar "por cima" dela.

Por que a imagem não "vaza" pra coluna do texto

A coluna da imagem (width:50%;overflow:hidden) é a moldura de novo — a mesma explicação lá do início da página. A imagem (a "foto") preenche só essa moldura de 50%, nunca a tela toda, porque a moldura dela é só metade da largura.

Por que a pausa em pixel funciona certinho

Como não escrevemos sw-premium-scroll-end na mão, o componente soma sozinho os pixels de cada sw-premium-frames-hold (mais uma folga padrão de 120px pra cada troca de bloco) e usa essa soma como o tamanho exato da rolagem. Resultado: 450px pedidos é 450px de verdade, não uma fração aproximada.

Como remover / desmontar

Duas situações diferentes:

Remover de vez (o normal)

Apague o bloco HTML inteiro (a <div sw-premium-frames-scrub> e o contêiner em volta). Não sobra nada rodando — o framework só ativa o que existe na página.

Desligar tudo via JavaScript

Se você trocar de página numa SPA/AJAX sem recarregar, chame window.SWPremium.destroy() — mata todos os ScrollTriggers ativos (frames, vídeo, parallax, tudo) de uma vez, sem vazar memória.

Boas práticas de peso

  • Quantidade de quadros: 30–100 é o ponto ideal pra a maioria dos efeitos. Mais que isso engorda a página sem melhorar muito a sensação de fluidez (o scroll humano não percebe diferença acima de ~60fps efetivos na troca).
  • Tamanho da imagem: gere no WebMotion Studio já no tamanho de exibição real (não use Full HD se a seção só tem 800px de largura na tela).
  • Qualidade WebP: o WebMotion usa quality=80 por padrão pros quadros — testado lado a lado com 96, sem diferença perceptível e 66% mais leve.
  • Mobile: abaixo de 768px o pin é desativado automaticamente (a seção não trava a tela) — o mesmo comportamento do sw-premium-video-scrub e de todos os outros efeitos com pin do framework. A troca de quadro continua funcionando, só sem travar a rolagem.
